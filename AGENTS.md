# Repository Guidelines

## Project Structure & Module Organization
- `llmlex/`: core library (e.g., `llmlex.py`, `kanlex.py`, `fit.py`, `llm.py`, `images.py`, `response.py`).
- `tests/`: pytest suite; `tests/archive/` is ignored by default. Test data lives in `tests/test_data/` and is generated by the runner.
- `Examples/`: usage examples and notebooks; see `readme.md`, `QUICK_START_LAMBDA_JSON.md`, `LAMBDA_JSON_GUIDE.md`.
- Top level scripts: `basic_usage.py`, `basic_usage_ha.py`, utilities, and assets (`logo.png`, `ha_image.png`).

## Build, Test, and Development Commands
- Install (dev): `pip install -e .` (from repo root).
- Run tests (summary): `python tests/run_tests.py --no-api`
- Run tests (verbose): `python -m pytest tests -v`
- With real API: set `OPENROUTER_API_KEY` (via shell or `.env`) and omit `--no-api`.
- Lint/format (if used locally): prefer PEP 8/black-compatible style; no enforced tool in repo.

## Coding Style & Naming Conventions
- Python 3; 4-space indentation; keep modules small and cohesive.
- Naming: modules `lower_snake_case.py`; functions/variables `lower_snake_case`; classes `CapWords`.
- Docstrings: concise one-liners for public functions/classes; include argument/return notes when nontrivial.
- Imports: standard library → third-party → local; avoid wildcard imports.

## Testing Guidelines
- Framework: pytest. Tests live under `tests/` and follow `test_*.py` naming.
- API tests: mark with `@pytest.mark.api`; skip via `--no-api`. Archived tests live in `tests/archive/` (ignored by default).
- Data: test data auto-generated by `tests/run_tests.py` before collection.

## Commit & Pull Request Guidelines
- Commits: imperative mood and concise scope (e.g., “Add fit optimizers”, “Refactor image generation”).
- PRs: clear description, rationale, and scope; link issues; include before/after results or logs when relevant; add/update tests.
- Keep changes focused; avoid unrelated refactors.

## Security & Configuration Tips
- Secrets: use `OPENROUTER_API_KEY` via environment or `.env`. Do not commit `.env` or keys (already in `.gitignore`).
- Be mindful of API costs/rate limits in tests; prefer `--no-api` for routine CI/local runs.
