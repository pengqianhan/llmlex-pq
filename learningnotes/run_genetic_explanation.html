🧬 run_genetic 函数详解

基于大语言模型的遗传算法符号回归详细教程

📖 函数概述

run_genetic 是一个创新的遗传算法实现，它使用大语言模型（LLM）来生成和优化数学公式，以拟合给定的数据。 与传统遗传算法不同，这个方法利用 GPT 等模型的数学理解能力来"进化"更好的函数表达式。

📋 参数说明

参数名 类型 说明
client object OpenAI 客户端对象，用于调用 LLM API
base64_image str 数据可视化图像的 base64 编码，让 LLM 看到数据分布
x array-like 输入数据（自变量）
y array-like 目标数据（因变量）
population_size int 种群大小，即每一代有多少个候选公式
num_of_generations int 进化代数，算法会迭代多少次
temperature float 选择温度参数，控制选择的随机性（默认 1.0）
model str 使用的 LLM 模型名称
exit_condition float 提前终止条件（归一化卡方值阈值，默认 1e-5）
elite bool 是否使用精英主义（保留最优个体）
plot_parents bool 是否在图像中显示父代公式的曲线

🔍 详细步骤解析

1初始化与基线检查

算法首先检查一个常数函数是否足够好。这是一个重要的优化，避免不必要的计算。

# 清除速率限制锁 clear_rate_limit_lock() # 初始化统计追踪器 api_stats = APICallStats() # 检查常数函数作为基线 curve = lambda x, *params: params[0] * np.ones(len(x)) params, _ = curve_fit(curve, x, y, p0=[1.0]) n_chi_squared = get_n_chi_squared(x, y, curve, params) if n_chi_squared <= exit_condition: # 常数函数已经足够好，直接返回 return populations
💡 为什么要检查常数函数？
如果数据本身就是一个常数（y ≈ c），那么没有必要运行复杂的遗传算法。这个检查可以节省大量的 API 调用费用。
常数函数: f(x) = c
归一化卡方: χ²_n = Σ(y_i - f(x_i))² / (N × var(y))

2生成初始种群（异步并行）

这是算法的核心创新之一：使用异步并行调用 LLM 来生成初始种群。

async def generate_population(): tasks = [] semaphore = asyncio.Semaphore(10) # 限制并发请求数为 10 async def create_individual(): async with semaphore: max_attempts = 5 for attempt in range(max_attempts): try: # 指数退避策略 backoff_time = 0.1 * (2 ** attempt) # 调用 LLM 生成公式 result = await async_single_call( client, base64_image, x, y, model=model, system_prompt=system_prompt, stats=api_stats, imports=imports ) if result is not None: return result await asyncio.sleep(backoff_time) except Exception as e: await asyncio.sleep(backoff_time) return None # 创建所有任务 for i in range(population_size): tasks.append(create_individual()) # 等待所有任务完成 results = await asyncio.gather(*tasks) return [r for r in results if r is not None] # 安全地执行异步代码 population = execute_async_in_loop(generate_population())

并行生成示意图

⚠️ 重要特性：
  • 信号量（Semaphore）：限制同时进行的 API 调用数量为 10，避免超出速率限制
  • 指数退避（Exponential Backoff）：失败后等待时间呈指数增长（0.1s, 0.2s, 0.4s, 0.8s, 1.6s）
  • 最多重试 5 次：每个个体最多尝试生成 5 次

3评估适应度与排序

生成的每个公式都需要被评估。适应度分数越高，公式越好。

# 处理非有限分数（NaN 和 Inf） non_finite_scores = [p for p in population if not np.isfinite(p['score'])] if non_finite_scores: finite_scores = [ind['score'] for ind in population if np.isfinite(ind['score'])] if finite_scores: min_score = min(finite_scores) bad_score = 2 * min_score if min_score < 0 else min_score - abs(min_score) else: bad_score = -1e8 # 将所有非有限分数设置为相同的坏分数 for p in non_finite_scores: p['score'] = bad_score # 按分数排序（分数越高越好） population.sort(key=lambda x: x['score']) populations.append(population) best_pop = population[-1] # 最后一个是最好的 # 检查是否满足退出条件 if best_pop['score'] > -exit_condition: return populations # 提前终止
💡 适应度分数说明：
分数 = -χ²_n（归一化卡方的负值）
• 分数越接近 0 越好（完美拟合时为 0）
• 负值越小，拟合越差
• NaN 或 Inf 表示拟合失败，会被赋予一个很低的分数

种群排序示例

4选择父代（基于温度的选择）

使用玻尔兹曼选择方法，根据适应度计算每个个体被选中的概率。

# 计算选择概率 scores = np.array([ind['score'] for ind in population]) finite_scores = scores[np.isfinite(scores)] # 归一化分数到 [0, 1] normalized_scores = (scores - np.min(finite_scores)) / (np.max(finite_scores) - np.min(finite_scores) + 1e-6) # 应用温度参数的 softmax exp_scores = np.exp((normalized_scores - np.max(normalized_scores)) / temperature) probs = exp_scores / np.sum(exp_scores) # 为每个新个体选择两个父代 selected_population = [ np.random.choice(populations[-1], size=2, p=probs, replace=True) for _ in range(population_size) ] # 提取父代的公式和参数 func_lists = [ [(pops[0]['ansatz'], pops[0]['params']), (pops[1]['ansatz'], pops[1]['params'])] for pops in selected_population ]
选择概率公式:

P(i) = exp(score_i / T) / Σ exp(score_j / T)

T = temperature（温度参数）
💡 温度参数的作用：
  • T → 0：几乎总是选择最好的个体（贪婪选择，可能陷入局部最优）
  • T = 1：平衡的选择（推荐值）
  • T → ∞：接近均匀随机选择（探索性强，但效率低）

5生成后代（基于父代）

这是算法最核心的创新：让 LLM 看到父代公式，并生成改进的后代公式。

async def generate_generation_population(): tasks = [] semaphore = asyncio.Semaphore(10) async def create_individual(idx): func_list = func_lists[idx] # 两个父代的公式 async with semaphore: for attempt in range(5): try: result = await async_single_call( client, base64_image, x, y, model=model, function_list=func_list, # 传入父代公式 system_prompt=system_prompt, stats=api_stats, plot_parents=plot_parents, # 可选：在图中显示父代曲线 imports=imports ) if result is not None: return result except Exception as e: pass return None # 创建新一代（如果使用精英主义，则少一个） for i in range(population_size - (1 if elite else 0)): tasks.append(create_individual(i)) results = await asyncio.gather(*tasks) return [r for r in results if r is not None] gen_population = execute_async_in_loop(generate_generation_population()) # 如果使用精英主义，保留上一代的最优个体 if elite: population = [best_pop] + gen_population else: population = gen_population

6精英主义（可选）

如果启用 elite=True，算法会保留上一代的最优个体，确保不会退化。

population = [] if elite: # 保留最优个体 population.append(best_pop) # 生成其余的新个体 gen_population = execute_async_in_loop(generate_generation_population()) if elite: population.extend(gen_population) else: population = gen_population

7迭代与终止

重复步骤 4-6，直到满足终止条件或达到最大代数。

for generation in range(num_of_generations - 1): # 选择父代 selected_population = select_parents(population, probs) # 生成后代 new_population = generate_offspring(selected_population) # 评估和排序 new_population.sort(key=lambda x: x['score']) best_pop = new_population[-1] populations.append(new_population) # 检查提前终止条件 if best_pop['score'] > -exit_condition: logger.info(f"Exit condition met after generation {generation+1}") return populations population = new_population # 打印统计信息 print(f"\n{api_stats}") return populations
💡 终止条件：
  • 达到目标精度：best_score > -exit_condition（例如，χ²_n < 1e-5）
  • 达到最大代数：完成所有代数的迭代

📤 返回值

返回类型：List[List[Dict]]

一个嵌套列表，其中：

  • 外层列表：每个元素代表一代（generation）
  • 内层列表：每个元素代表一个个体（candidate formula）
  • 字典包含以下键：
    • params: 拟合参数
    • score: 适应度分数（-χ²_n）
    • ansatz: 公式字符串
    • Num_params: 参数个数
    • response: LLM 原始响应
    • prompt: 使用的提示词
    • function_list: 父代公式列表（如果有）

⚖️ 优势与局限性

✅ 主要优势

  • 强大的数学理解：LLM 可以理解复杂的数学模式和结构
  • 视觉理解：可以"看到"数据的可视化，直观理解趋势
  • 灵活的表达：不受预定义函数集的限制
  • 高效的并行化：异步并行大幅提升速度
  • 自适应进化：能够组合父代的优点创造更好的后代

⚠️ 局限性

  • API 成本：每次调用 LLM 都有费用（特别是 GPT-4）
  • 不确定性：LLM 的输出有随机性，可能需要多次尝试
  • 速率限制：API 有调用频率限制
  • 复杂度：对于简单问题可能过于复杂
  • 可解释性：LLM 如何"想出"公式的过程是黑盒

🎓 总结

run_genetic 是一个创新的符号回归方法，它将遗传算法的进化思想与大语言模型的数学理解能力相结合。 通过让 LLM "看到"数据并基于父代公式生成改进的后代，这个方法能够发现复杂的数学模式， 而无需预定义函数库。这是人工智能在科学发现领域的一个激动人心的应用。
